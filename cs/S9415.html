S9415 — Local functions should be marked "static" when they don't capture variables

Language
C#
Type
Code smell
Severity
Major
Tags
clarity, idiomatic

This rule raises an issue when a nested function does not use any variables from its enclosing scope but is not marked with a qualifier indicating it doesn’t capture outer variables.

Why is this an issue?

Nested functions can access variables from their enclosing scope (known as "capturing" or "closing over" variables). When a nested function doesn’t capture any variables, it is completely independent of the surrounding function’s state.

Some languages provide mechanisms to explicitly mark nested functions as non-capturing, making this independence explicit. When you mark a nested function as non-capturing, you are communicating to other developers that:

  • The function operates independently of the enclosing scope
  • The function cannot accidentally capture variables in the future
  • The function’s behavior depends only on its parameters

Without such explicit marking, readers must examine the entire function body to determine whether it captures variables. This creates unnecessary cognitive load and makes the code’s intent less clear.

Additionally, language tools can prevent accidental captures when a function is explicitly marked as non-capturing. If someone later tries to use a variable from the enclosing scope, the compiler or linter will produce an error, preventing subtle bugs.

In C#, this mechanism is the static modifier for local functions, introduced in C# 8.0.

What is the potential impact?

The impact of this issue is limited to code maintainability and clarity:

  • Reduced code clarity: Without explicitly marking the nested function as not accessing outer scope, developers must read the entire function to understand its dependencies
  • Harder maintenance: Future modifications might accidentally introduce variable captures, changing the function’s behavior in unexpected ways
  • Missed optimization opportunities: In some cases, the compiler may generate slightly more efficient code for nested functions that are marked as not capturing variables because it knows no closure allocation is needed

In C#, nested functions are marked with the static modifier to indicate they don’t capture variables from the outer scope.

How to fix it

Add the static modifier to the local function declaration. This explicitly marks the function as independent of the enclosing scope.

Code examples

Noncompliant code example


void ProcessData()
{
    Console.WriteLine(FormatText("test  "));

    string FormatText(string input) => input.Trim(); // Noncompliant
}

Compliant solution


void ProcessData()
{
    Console.WriteLine(FormatText("test  "));

    static string FormatText(string input) => input.Trim();
}
